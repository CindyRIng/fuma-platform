# 运维部署手册

> 适用：NixOS / Linux 单机部署（systemd user service）。项目目录示例 `~/fuma-platform`。
> 数据目录默认 `~/.fuma-platform`（可用 `FUMA_HOME` 覆盖）。

## 1. 前置条件

| 项 | 要求 |
|---|---|
| OS | NixOS / Linux（x86_64） |
| Node | ≥ 22.5（本项目在 v22.23.2 验证）；`node:sqlite` 需 `--experimental-sqlite` |
| 浏览器 | cloakbrowser 0.6.5 + Chromium（登录/扫码用）；NixOS 下需通过 `~/cloak-env/bin/cloak-run` 运行 |
| 网络 | 可访问 `www.fumamx.com`、`login.dingtalk.com`、`cdnstatic.fumamx.com` |
| 磁盘 | ≥ 2GB（海关缓存上限默认 2GB，可调） |

## 2. 安装（一键）

```bash
cd ~/fuma-platform
cp .env.example .env && chmod 600 .env   # 可选：填写登录凭证（扫码登录可留空）
./scripts/install.sh
```

脚本会：安装依赖 → 构建 → 初始化 `~/.fuma-platform` → 生成 systemd user unit → 启动服务。
仅安装不启动：`./scripts/install.sh --no-start`。

## 3. 手动安装（等价步骤）

```bash
cd ~/fuma-platform
npm install --no-audit --no-fund
npm run build
FUMA_HOME=~/.fuma-platform node --experimental-sqlite --import tsx src/main.ts doctor
mkdir -p ~/.config/systemd/user
cp deploy/fuma-platform.service ~/.config/systemd/user/
# 按需修改 ExecStart（claw-run / node 路径）
systemctl --user daemon-reload
systemctl --user enable --now fuma-platform
```

## 4. 服务管理

```bash
systemctl --user status fuma-platform
systemctl --user restart fuma-platform
systemctl --user stop fuma-platform
journalctl --user -u fuma-platform -f          # 实时日志
```

日志文件：`~/.fuma-platform/logs/app.jsonl`（JSONL，敏感字段已脱敏）。建议 logrotate 或 journald 归档。

## 5. 初始配置

### 5.1 查看 API Token
```bash
node -e "console.log(JSON.parse(require('fs').readFileSync(process.env.HOME+'/.fuma-platform/config.json','utf8')).server.apiToken)"
```

### 5.2 创建账号
```bash
fuma account create acct_01 \
  --name "业务员A" --owner-name "业务员A" \
  --dingtalk-org "上海孚盟软件有限公司" \
  --fuma-enterprise "上海孚盟软件有限公司"
```
（`fuma` = `node --experimental-sqlite ~/fuma-platform/dist/main.js`；建议加 alias 或 `npm link` 后使用 `fuma`。）

### 5.3 扫码登录
```bash
fuma session login acct_01
```
终端会打印二维码；用钉钉扫码确认后自动完成组织/企业选择并进入工作台（在线状态写入 DB）。
也可通过 REST：`POST /v1/accounts/acct_01/session/login` 后用 `GET .../session/qr` 取二维码（含 pngBase64）。
登录环节需要人工扫码；后续心跳保活、到期重登由后台调度器处理（重登需再次扫码，若免扫码实验成功则自动）。

### 5.4 验证
```bash
TOKEN=<apiToken>
curl -s -H "Authorization: Bearer $TOKEN" http://127.0.0.1:17890/v1/health
curl -s -H "Authorization: Bearer $TOKEN" http://127.0.0.1:17890/v1/accounts
curl -s -H "Authorization: Bearer $TOKEN" -X POST http://127.0.0.1:17890/v1/customers/list \
  -H 'content-type: application/json' -d '{"page":1,"pageSize":5}'
```

## 6. 备份与恢复

```bash
# 备份（VACUUM INTO）
fuma backup --dest ~/.fuma-platform/backups/fuma-$(date +%F).db
# 同时备份密钥（token 加密 key，必须与 DB 一起保存）
cp ~/.fuma-platform/secret.key ~/.fuma-platform/backups/secret-$(date +%F).key && chmod 600 ~/.fuma-platform/backups/secret-*.key
```
恢复：停止服务 → 用备份 DB 覆盖 `~/.fuma-platform/data/fuma.db`（同时恢复对应 `secret.key`）→ 启动服务。
建议 cron 每日备份并保留 7 份。

## 7. 升级与回滚

```bash
cd ~/fuma-platform
git pull && npm install --no-audit --no-fund && npm run build
systemctl --user restart fuma-platform
```
回滚：`git checkout <tag>` → 重新构建 → 重启。
SQLite schema 迁移在启动时自动执行（`schema_migrations`），升级前请先备份。

## 8. 监控与告警

- 健康检查：`GET /v1/health`（lite：DB/账号在线数）。
- 详细状态：`GET /v1/status`（账号明细、同步队列、任务）。
- 关键指标建议监控：账号在线率、心跳失败数、outbox pending/failed、任务积压、缓存命中率。
- 事件：`GET /v1/events?sinceSeq=` 轮询（事件保留 30 天）。
- 日志：`~/.fuma-platform/logs/app.jsonl`。

## 9. 常见故障排查

| 现象 | 排查 |
|---|---|
| 服务起不来 | `journalctl --user -u fuma-platform -n 100`；检查 Node 版本、`--experimental-sqlite`、端口占用（17890） |
| 登录弹窗失败 | 是否在 NixOS 且通过 `cloak-run` 运行；检查 `~/.cloakbrowser` 浏览器是否存在 |
| 全部读接口 session_expired | 账号未登录或 token 过期：`fuma session status acct_01` → `fuma session login acct_01` |
| 领取返回 duplicate_customer | 强制先查后领命中查重；按业务确认后由编排层处理 |
| 领取 capacity_exceeded | 账号容量上限（默认 500，按角色规则）；释放或换账号 |
| 同步一直 failed | `GET /v1/sync/status` 查看 outbox 错误；修复后 `POST /v1/sync/outbox/retry` |
| 海关查询慢 | 首次走上游；后续命中缓存（`cached=true`）；可用 `forceRefresh` 刷新 |
| 删除客户报 1114/无权限 | 当前账号无客户删除权限（上游角色限制），需管理员处理或换有权限账号 |

## 10. 安全

- `.env` 与 `~/.fuma-platform/secret.key` 权限 600，禁止提交/外发。
- REST 仅监听 127.0.0.1；MCP 走 stdio；对外暴露需自行加网关与鉴权。
- token 使用 AES-256-GCM 加密存储；日志/事件脱敏。
- 反代/WebUI 场景务必保持本机监听并加 TLS/鉴权。
- 合规：账号为真实业务员账号，平台独占；请遵守孚盟使用条款，控制访问频率。
