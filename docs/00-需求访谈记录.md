# 00 需求访谈记录（截至 2026-11-14）

## 1. 系统定位

`fuma-platform` 是 `main` 大系统中的**上游适配子系统**，只负责孚盟（fumamx.com）这一侧：

- 孚盟 = 公司的**客保库**（客户保护/归属的最终事实）+ 海关数据源。
- `fuma-platform` = 孚盟的**薄封装**：多账号会话池 + 请求池 + 客户管理/海关数据能力 + 本地事实与事件。
- `lead platform` = **业务编排层**（决定查谁、何时查重/查海关、领到哪个账号、何时建档/跟进/释放），调用 fuma-platform 执行并消费其事件。
- `Twenty CRM` = 业务数据中枢；与外部系统如何交互**暂不讨论**，本阶段只保证封装干净。

## 2. 能力范围（定稿）

✅ 客户管理：
- 客户查重（单条 / 批量 ≤200 / AI 查重）
- 客户档案：列表 / 详情 / 新建 / 编辑
- 公海客户：列表 / 详情 / 领取 / 释放
- 客户联系人：**读写**
- 客户跟进记录：**读写**（必做）
- 保护状态 / 掉保预测 / 掉公海原因
- 账号客保容量查询

✅ 海关数据：
- 贸易大数据：按公司查 / 按产品查 / 交易分析

✅ 基础设施：多账号会话管理、扫码/账密登录与会话保活、RequestPool、任务化批量任务、本地事实与同步、事件（outbox，消费方后续再接）

❌ 不做：线索/商机、邮件/询盘、营销、报价/订单/单证、采购/库存/财务、沟通/WhatsApp、知识库、报表、贸易监测（默认不做）

## 3. 关键设计前提

1. **账号 = 真实业务员账号**，但平台做好后真人不再直接操作该账号，平台是唯一操作者 → 本地优先可行，对账主要处理孚盟服务端规则触发的变化。
2. **写操作必须显式传 `accountId`**（外部调用方指定），平台只做校验（客保容量/3 天冷却/保护状态/账号在线）与执行，**不替调用方选账号**。
3. 规模：3–50 个账号 → 客保容量按默认 500 估算 1500–25000（实际上限按角色规则 300/200/500）。
4. 上游风控强度、调用频率上限**未知** → 默认保守限速 + 自适应限流 + 熔断/告警，P0 低频探测。
5. **本地优先**：本地写入即事实 → outbox 异步同步上游；冲突细则后续单独讨论。
6. **批量任务任务化**：持久化 taskId + 状态机（排队/运行/成功/失败/取消），支持并发度、重试、结果查询。
7. 登录：目标是扫码登录（CLI 终端渲染二维码、REST 返回 Base64）；当前已知登录需选租户「上海孚盟软件有限公司」并弹钉钉验证。
