## 3. 会话与鉴权

### 3.1 Token 结构（实测）

```json
// accessToken（企业维度，24h）
{"ownerId":13148056,"scope":"13148056","value":"<32位>","createTime":1794661506381,
 "expireTime":1794747906381,"cid":10264,"platform":"pc","readOnly":0,"versionIteration":1}
// individualAccessToken（个人维度，24h）
{"ownerId":12491921,"scope":"independent","value":"<16位>","createTime":1794661498027,
 "expireTime":1794747898027,"cid":null,"platform":"pc"}
```
- 有效期 24h（expireTime-createTime=86400000）。
- **无 refresh 接口**；过期只能重新登录（见 06 保活设计）。
- 上游 token 轮换：每次登录新 token，旧 token 是否立即失效未验证（P2 需验证「多 token 并存」与「旧 token 宽限」）。

### 3.2 注入方式

| 方法 | 注入 |
|---|---|
| GET | query：`accessToken=<A>&individualAccessToken=<B>&_filterCompanyId=10264` |
| POST | JSON body：`{"accessToken":"<A>","individualAccessToken":"<B>","_filterCompanyId":10264, ...}` |

### 3.3 公共参数（所有 /pcapi）

```
event_source=MX
operating_terminal=pc_网页端（URL encode）
languageForMX5=en|zh-cn
isV5=true
isV5AndNewMail=true
_filterCompanyId=10264
isNewArchCompany=true
```
GET 另带 `_@#time=<毫秒>`（URL encode 为 `_%40%23time=`）。

### 3.4 公共请求头

```
accept: application/json, text/plain, */*
content-type: application/json;charset=UTF-8   (POST)
x-requested-with: XMLHttpRequest
referer: https://www.fumamx.com/
user-agent: Mozilla/5.0 ... Chrome/146.0.0.0 Safari/537.36
x-trace-id: <32 hex>（可自造）
```

### 3.5 响应 envelope

```json
{"code":"0","data":{},"ApiTime":0.49,"version":"bc606bee...","releaseVersion":20261113115144,
 "updateLevel":"major","updateNotify":false,"node":"prod_new@...","traceId":"..."}
```

### 3.6 错误码

| code | 含义 | 处理 |
|---|---|---|
| `0`/`"0"` | 成功 | — |
| `-1` | 系统繁忙/参数缺失 | 退避重试（有限） |
| `-2` | 未登录/鉴权失败 | 会话失效 → 重登 |
| `-1000` | 参数/系统异常（`msg.errorMessage` 含 Java 异常） | 不重试，记录并告警 |
| `1007` | 上游业务错误（权限/参数） | 不重试 |
| DingTalk `11021` | 二维码未扫/失效 | 刷新二维码 |
| DingTalk `11041` | 已扫待确认 | 等待 |

## 4. 通用查询协议（列表类）

### 4.1 统一列表接口

`POST /pcapi/bill/bill/get_page_list`

```json
{
  "recoveryFlag": false,
  "moduleCode": "NewBF001",
  "organizationStructure": { "type": 3, "ownerCtIdList": [] },
  "page": { "from": 0, "size": 50 },
  "orderBy": { "desc": "desc", "realFieldName": "create_date", "tableCode": "1" },
  "searchFieldCondition": { "seasFlag_eq": 1 },
  "subBill": { "originModuleCode": "NewBF001", "targetModuleCode": "NewBF003", "keyId": "<masterKeyId>" },
  "...": "公共参数 + tokens"
}
```

- `page.from` 为偏移量；响应 `data.totalNum` + `data.list`（每条含原始字段 + `_convert` 展示字段）。
- `orderBy.realFieldName`：`create_date`/`primary_contact` 等。
- 已见筛选操作符：`_eq`、`_notin`（如 `trackMode_notin:"7,8,10,200,201"`）。
- 已补：完整操作符全集（48 comparator）与字段目录（51 字段）见附录 v3 §A；`searchFieldCondition` 的「字段_操作符后缀」映射在 P2 用一次高级筛选核对。
- 汇总接口：`POST /pcapi/bill/bill/get_page_list_sum`（同 body）。

request(method, path, { accountId, body/query, idempotencyKey })

  if method GET: url = base+path+'?'+query(params+queryParams)
  else: body = { ...body, ...commonParams(), ...tokenFields() }
  resp = http(url, method, body, headers)
  if resp.code == '0' return resp.data

  if resp.code == '-1' or network: retry(backoff)
  else: raise UpstreamError(resp.code, resp.msg)

### 5.3.2 领取（doReceive / doBatchReceive）

### 5.3.3 删除（doDelete / doBatchDelete）

### 5.3.4 建档 / 编辑（addSingleCustomer / edit_customer）

新建客户走 **QuickAddPage** 流程：页面先组装

```

```
服务端字段名与 `get_page_info/get_edit_config` 返回的字段模型一致（fieldName/realFieldName/fieldId 三套映射）。
平台实现直接构造「customer 字段 map + contact 数组」，转换逻辑按 `L.c` 在 P2 联调时对齐（已抓到完整表单字段模型，无需再逆向前端）。

## 附：v6 筛选后缀映射实测（2026-11-15 00:40）

对 `POST /bill/bill/get_page_list` 的 `searchFieldCondition` 做了实测（客户模块）：

| 语义（comparator） | JSON 后缀 | 实测示例 | 结果 |
|---|---|---|---|
| CONTAIN（包含） | `_like` | `{"custName_like":"ZZ_TEST"}` | ✅ 命中 4 条（正确过滤） |
| IS（等于） | `_eq` | `{"custName_eq":"ZZ_TEST_FUMA_E2E_010214"}` | ✅ totalNum=1 |
| NOT_IN | `_notin` | `{"trackMode_notin":"7,8,10,200,201"}` | ✅ 实测（跟进列表） |
| `_in` | — | `{"custName_in":"ZZ_TEST"}` | 值为字符串时 totalNum=0（可能要求数组/特定格式，待补） |

结论：平台 `filters` 透传时，文本包含请使用 `字段_like`；等值使用 `字段_eq`；更多 comparator 后缀（NULL/BETWEEN/相对日期等）
建议用高级筛选 UI 逐项核对后补全（P7）。
