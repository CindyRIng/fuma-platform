# 性能与容量报告

> 生成时间：2026-11-15 00:30 ｜ Node v22.23.2 ｜ 数据为 mock 上游（2ms 网络延迟）+ 本机 SQLite。

## 1. 基准结果（`npm run bench`）

### 客户读取（50 账号池、200 次读）

| 指标 | 值 |
|---|---|
| 样本 | 200 |
| p50 | 3.29 ms |
| p95 | 3.78 ms |
| QPS | 280.5 |

说明：mock 上游固定 2ms + SQLite upsert/查询开销；真实上游实际耗时以网络为准（通常 100–500ms）。

### 海关本地缓存（50 个不同查询 + 500 次重复查询）

| 指标 | 上游 | 缓存命中 |
|---|---|---|
| p50 | 2.74 ms | **0.11 ms** |
| p95 | 3.13 ms | **0.15 ms** |
| 命中率 | — | **100%** |
| 缓存条目 | 50 | — |

结论：缓存命中比走上游快约 **25 倍**；真实场景收益更大（省去网络与上游处理）。

### Outbox 同步吞吐（100 个领取操作）

| 指标 | 值 |
|---|---|
| 处理量 | 100 ops |
| 总耗时 | 279 ms |
| 吞吐 | **358 ops/s** |

结论：同步 worker 吞吐受上游限速（默认写 1 QPS/账号）约束；本测试关闭限速以测管线能力。
生产环境建议按账号数水平扩展（50 账号 ≈ 50 QPS 理论写吞吐上限）。

## 2. 优化项（已做）

- SQLite：WAL、`synchronous=NORMAL`、`busy_timeout=5000`、`cache_size=-65536`、`temp_store=MEMORY`、`mmap_size=256MB`。
- 索引：customers(account/seas/will_in_sea/sync)、outbox(status,next_retry)、events(seq/type)、tasks(status)、customs_cache(expires/used/type)。
- 语句缓存（prepared statement cache）与单写者事务队列。
- 请求池：账号级串行 + QPS 间隔 + 抖动，避免触发风控。
- 海关缓存：gzip 压缩、TTL、更新日志水位失效、LRU 容量上限（默认 20 万条/2GB）。
- 缓存命中路径无上游请求、无事件写入（仅 hit_count/updated 更新）。
- 读任务路由：优先选择最近可用账号，避免单账号热点。

## 3. 容量估算

| 项 | 估算 |
|---|---|
| 50 账号 × 500 客户 | 25,000 客户记录（+ 联系人/跟进） |
