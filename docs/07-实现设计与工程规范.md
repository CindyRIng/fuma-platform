## 3. 核心模块接口（契约级伪码）

### 3.1 Store

```ts
interface Store {
  tx<T>(fn: (tx: Tx) => Promise<T>): Promise<T>;       // BEGIN IMMEDIATE，单写者
  migrate(): Promise<void>;
  customers: CustomerRepo; contacts: ContactRepo; followups: FollowupRepo;
  sessions: SessionRepo; accounts: AccountRepo; outbox: OutboxRepo;
  tasks: TaskRepo; events: EventRepo; capacity: CapacityRepo;
  dedup: DedupRepo; customs: CustomsCacheRepo; reconcile: ReconcileRepo;
}
```

### 3.2 UpstreamClient

```ts
interface UpstreamClient {
  call<T>(accountId: string, req: UpstreamRequest, opts?: { idempotencyKey?: string; timeoutMs?: number }): Promise<T>;
}
type UpstreamRequest = { method: 'GET'|'POST'|'PUT'; path: string; query?: Record<string,unknown>; body?: Record<string,unknown> };
// 内部：token 注入、公共参数、错误映射、重试（-1/网络/超时）、-2 触发会话失效事件
```

### 3.3 SessionManager

```ts
interface SessionManager {
  prewarm(accountId: string): Promise<void>;
  startLogin(accountId: string, mode?: LoginMode): Promise<{ state: SessionState }>;
  getQr(accountId: string): Promise<QrPayload>;          // payload + pngBase64 + expiresAt
  getState(accountId: string): Promise<SessionView>;
  cancelLogin(accountId: string): Promise<void>;
  logout(accountId: string): Promise<void>;
  ensureValid(accountId: string): Promise<Session>;      // 供 UpstreamClient 使用
```

### 3.4 RequestPool

```ts
interface RequestPool {
  submit<T>(task: PoolTask<T>): Promise<T>;   // 读任务路由任意在线账号；写任务必须 accountId
  status(): PoolStatus;                        // 各账号水位/限速/熔断
  on(event: 'pool.rate_limited'|'account.circuit_open', cb): void;
}
```

## 4. 关键时序

### 4.1 登录（快路径）

```
API(login) → SessionManager.startLogin
  ├─ prewarm: 复用常驻浏览器页 → 点击钉钉
  ├─ popup 就绪 → 监听 login_with_qr 响应 + canvas 出现
  ├─ canvas.toDataURL → ZXing 解码 → qrcode 重编码 → 发 session.qr.ready
  ├─ 11041 → 发 session.login.scanned
  ├─ success → 精确点组织 → 监听 thirdPartyAuthSuccess
  ├─ 回跳 → 轮询企业选择 DOM → 选企业+进入
  ├─ 监听 sessionStorage.accessToken → 采集 → 加密存 sessions
  └─ online → 启动心跳（keepalive）
```

### 4.2 读列表（缓存优先）

```
API(customer.list) → Store 查缓存（stale 判断）
  命中且未过期 → 返回
  未命中/forced → RequestPool.submit(read)
    → UpstreamClient.call(account, get_page_list)
    → 校验 contracts → Store upsert（customers）→ 返回
```

### 4.3 领取（本地优先 + 规则）

```
API(open-sea.claim, accountId, customerId, idempotencyKey)
  → idempotency 查重
  → RuleEngine.validateClaim（容量<500 / 冷却3天 / 公海状态 / 会话有效）
  → tx { customers.upsert(owner=accountId, seasFlag=0, syncState=pending)
         capacity_ledger(+1)
         outbox(doReceive, payload)
         events(open_sea.claimed pending) }
  → 返回 pending
  → SyncEngine worker → doReceive 成功 → syncState=synced + event
                      → 失败 → failed/重试/告警（策略见 05）
```

### 4.4 批量查重（任务化）

```
API(dedup.batch, keywords[≤200])
  → tasks.create(queued) → worker 分片（每片 1 个 keywords）
  → RequestPool.submit(read, repeat/check)（可合并去重）
  → results 写 dedup_snapshots/task_items → task progress
  → 完成事件 dedup.result.changed（有变化时）
```

### 4.5 保活/重登

```
Every 240s: keepalive → personalsettingGet
  成功 → session_health 写记录；token 剩余<45min → 发 session.expiring，入重登队列
  失败(3次) → degraded；-2 → expired → 重登队列
重登队列 worker（并发≤2）:
  silentRelogin 尝试 → 成功则静默切换（新 token 落库，旧 token 校验宽限）
  失败 → 生成二维码 → 发 session.qr.ready（需人工）→ 扫码后自动完成
```

## 5. 并发模型

- 单进程 + 事件循环；长任务走独立 worker（池大小可配）。
- SQLite 单写者：所有写操作经 Store.tx 串行（BEGIN IMMEDIATE），读并发（WAL）。
- 账号锁：同账号登录/重登互斥（内存 Mutex + DB 状态）；业务请求按账号并发限速。
- RequestPool：每账号 token bucket + 全局并发上限；队列按优先级（登录>写>读>批量）。
- 任务：tasks 表 + worker 领取（`SELECT ... status='queued'` 原子更新）；支持重启恢复（running 标 interrupted）。

## 6. 错误处理与重试矩阵

| 分类 | 例子 | 策略 |
|---|---|---|
| 参数/校验 | -1000（非系统异常） | 不重试，返回 `invalid_argument`/`upstream_error` |
| 鉴权 | -2 | 会话 expired 事件 → 重登；当前请求失败返回 `session_expired` |
| 可重试上游 | -1、timeout、5xx、网络 | 指数退避 ≤3 次；批量任务计入失败明细 |
| 业务冲突 | 重复建档/冷却/容量 | 返回明确错误码，不重试 |
| 限流 | 429/账号熔断 | 返回 `rate_limited` + retryAfterMs |
| 内部 | DB 锁/未知异常 | 返回 `internal_error`，记录 requestId 与堆栈（脱敏） |

重试原则：**写操作仅在带 idempotencyKey 且上游允许时重试**；默认写不自动重试，由 outbox 重试（本地事实不丢）。

## 7. 测试策略

1. **单元测试**：规则引擎、状态机、错误映射、QR 编解码、脱敏。
2. **契约测试（mock）**：fixtures 保存真实响应样本（脱敏），验证 zod schema 与解析。
3. **真实上游只读探针**：每日/发版后跑一次（客户列表/查重/公海首页/海关初始化），失败告警；只读不改数据。
4. **登录 E2E**：需人工扫码标记（`FUMA_E2E=1`），验证二维码、组织/企业选择、token 落库、保活。
5. **恢复测试**：kill -9 重启；未完成任务/outbox/本地事实完整性。
6. **并发/压测**：50 账号 × 限速模拟；任务积压/背压；内存/句柄泄漏。
7. **风控演练**：模拟 -2、超时、-1000、连续失败熔断。

## 8. 可观测性

- 结构化日志（JSONL）：`ts, level, reqId, accountId, action, latencyMs, upstreamCode, error`；token/cookie 脱敏。
- 指标（可日志聚合/后续接 Prometheus）：在线账号数、登录耗时、心跳延迟/失败率、池水位、任务积压、同步队列、错误码分布。
- 健康检查：`/v1/health`（DB、会话、池）；`/v1/status`（详细）。
- 审计：所有写操作记录 `audit_log`。

## 9. 安全

- token/profile 加密 + 600；key 与 DB 分离；备份同时备份 key。
- REST 仅 127.0.0.1；Bearer token 必须；MCP stdio。
- 日志/事件/错误消息脱敏（accessToken/individualAccessToken/cookie）。
- 依赖最小化；`npm audit` 纳入 CI；秘密扫描。

## 附：海关缓存实现要点 v7（2026-11-14 23:55）

### 模块
- `src/customs/cache.ts`：cacheKey 计算、get/set、TTL、stale、LRU、命中统计。
- `src/customs/query.ts`：上游调用 + 并发合并（in-flight dedupe）+ 失败降级（stale）。
- `src/customs/update-log.ts`：定期读取 GetTradeUpdateLog，维护水位（`customs_cache_meta`），水位变化→标记 stale。

### 关键流程
```
customs.query(params, cacheOpts)
 → 计算 cacheKey（queryType|paramsHash|page|scope）
 → useCache && !forceRefresh: cache.get → 命中且未过期 → 返回 source=cache
 → 未命中/过期/force: 合并同 key 在途请求
     → 调上游 → 成功后写缓存（ttl 默认 24h）→ 返回 source=upstream
     → 上游失败 → allowStale 且有过期缓存 → 返回 source=cache, stale=true + 告警
 → 后台任务：每 N 分钟检查 update-log 水位；LRU 淘汰；90 天清理
```

### 测试
- 单测：cacheKey 规范化（同一查询不同参数顺序 → 同 key）、TTL/stale/LRU。
- 契约：缓存命中不产生上游请求（mock UpstreamClient 计数）。
- 集成：上游超时 → stale 返回；forceRefresh → 刷新；权限不同 → 不串缓存。
- 性能：10 万条缓存下查询命中 P95 < 50ms；并发合并有效。
