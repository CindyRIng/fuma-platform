# 05 数据模型与同步设计

> 目标：**本地事实层**（SQLite）+ **规则引擎** + **同步/对账** + **请求池/任务/事件**。
> 设计原则：本地优先、可重放、可对账、可恢复；上游规则作为本地不变式。
> 状态：v4（P1 设计基线 + v3/v4/v5 附录；未实现）。

## 1. 存储选型

- SQLite（WAL 模式，单写者）；文件 `~/.fuma-platform/data/fuma.db`。
- 单机 3–50 账号规模足够；后续可平滑迁 Postgres（表结构保持通用 SQL）。
- 加密：token/敏感字段应用层 AES-GCM 加密后存 BLOB/TEXT（base64）。
- 备份：每日 `VACUUM INTO` 快照 + 保留 N 份；迁移用 `schema_migrations`。

## 3. 关键状态机

### 3.1 会话状态
```
idle → starting → qr_ready → scanned → confirmed → org_selected → redirected → enterprise_selected → online
任意 → expired / failed / cancelled
```

### 3.2 客户保护状态（本地规则）
```
(无) --claim/build--> protected --15天无跟进--> expiring --到期--> public_sea
protected --release--> released --3天冷却--> 可再次领取
public_sea --claim--> protected
```
- `protected`：`seas_flag=0` 且归属某账号；容量 +1
- `expiring`：`will_in_sea_at - now < 阈值`；发 `protection.expiring`
- `public_sea`：`seas_flag=1`；容量 -1
- `released`：记录释放时间（用于 3 天冷却校验）

### 3.3 同步状态
```
local_committed (pending) → syncing → synced
                       ↘ failed → (retry) → synced / dead(人工)
```

### 3.4 任务状态
```
queued → running → succeeded / failed / partial / cancelled
running → interrupted（进程重启）→（策略）重跑或失败
```

## 4. 规则引擎（本地不变式）

| 规则 | 实现 | 配置来源 |
|---|---|---|
| 15 天保护期 | 客户 `protect_start_at/last_track_at` 计算 `will_in_sea_at`；每 5min 扫描到期 → 标记 public_sea（pending 同步）+ 事件 | 上游 seasRules/highseas 读取 + 本地配置默认 15 |
| 3 天释放冷却 | `released` 记录（accountId + releasedAt + customerId）；领取前校验 | 上游配置/本地默认 3 |
| 容量上限（默认 500） | 每账号保护客户计数（`customers` where seas_flag=0 and account_id）；领取前校验；容量账本事件溯源 | 上游 custLimit 角色规则 + 本地默认 500 |
| 查重复核 | `dedup_snapshots.checked_at`；定时任务按老化阈值重查；变化发事件 | 本地配置（如 7 天） |
| 保护期预警 | `will_in_sea_at` 距今天数 ≤ 阈值（如 3 天）→ 事件 | 本地配置 |

> 规则数值以**上游配置为准**：启动时（或定期）读取公海规则/容量配置；读不到时用本地默认值并标注 `configSource=default`。

## 5. 本地优先写路径（Local-first）

```
1. 调用方 → 能力层：校验参数/账号/权限/规则（容量、冷却、查重可选）
2. 开启事务：
   a. 写业务表（customers/contacts/followups/capacity_ledger）
   b. 写 sync_outbox（status=pending, idempotency_key）
   c. 写 events（本地状态变更事件）
   d. 更新本地保护状态字段（will_in_sea_at 等）
3. 提交事务 → 立即返回（data + syncState=pending）
4. SyncWorker：
   a. 取 pending outbox（FOR UPDATE 模拟：单写者）
   b. 调上游接口（带账号 token）
   c. 成功：更新业务表 sync_state=synced / 上游 id；outbox=succeeded；写 customer.synced 事件
   d. 失败：outbox=failed + next_retry_at（指数退避）；超过上限 → dead + 告警事件
5. 失败/冲突策略（已确认）：
   - 不回滚本地事实；标记 sync_failed/conflict 并告警
   - 对账冲突时**收敛到上游**（upstream_wins），写 sync.conflict 事件与审计
   - 不使用 `reverted`/`local_kept` 状态
```

**幂等**：
- 本地写：`idempotencyKey` 唯一索引，重复请求直接返回首次结果。
- 上游写：上游接口本身可能非幂等（如建档），因此 outbox 必须"先查后写"或依赖创建后回查去重（实现阶段设计）。

## 6. 上游对账（Reconcile）

### 6.1 触发
- 定时（默认 5–15 分钟，可配置）；
- 关键动作后（领取/释放/跟进/同步失败）；
- 手动 `POST /v1/sync/reconcile`。

### 6.2 拉取
- 客户列表增量：`bill/bill/get_page_list`（按 `modify_date`/分页；如支持时间过滤）；
- 公海列表：`seasFlag_eq=1`；
- 跟进：`v2/custTracks/get`；
- 容量：`bill/custLimit/get`（或本地计数校准）。

### 6.3 Diff 与冲突矩阵

| 场景 | 本地 | 上游 | 处理 |
|---|---|---|---|
| 本地 pending 未同步，上游无该动作 | pending | 无 | 继续同步（重试） |
| 上游已发生动作（领取/释放/跟进/掉保） | 旧状态 | 新状态 | **上游优先**：更新本地 + 事件（`sync.conflict` 记录） |
| 本地 pending 写 vs 上游已由他人修改 | 本地意图 | 上游新值 | 上游事实保留；本地写任务标记 `conflict`，告警人工裁决（默认不覆盖） |
| 删除/回收站 | 存在 | 已删 | 本地标记 deleted + 事件 |
| 容量不一致 | 账本计数 | 上游计数 | 以上游为准校正账本（写 reconcile_diff） |

### 6.4 对账报告
`reconcile_runs` + `reconcile_diffs` 持久化；`GET /v1/sync/status` 暴露；差异可人工查看。

## 7. 请求池设计

- **资源**：账号会话（online 且未暂停）。
- **任务类型**：
  - 读任务（列表/详情/查重/海关/监测）：可路由任意在线账号（按 优先级+水位+容量）。
  - 写任务（领取/释放/建档/跟进）：必须指定账号，仅校验该账号。
- **限速**：账号级 token bucket（默认读写各 1–2 QPS，随机抖动 100–500ms；可配置）；池级并发上限。
- **失败处理**：可重试错误（-1/超时/网络）退避重试；会话失效 → 标记账号 expired + 切换/等待重登；业务错误（-1000/1007）不重试，直接返回。
- **合并去重**：同 (`query_type`, `keywords_hash`) 的在途请求合并（查重/海关）；结果共享。
- **熔断**：账号连续 N 次失败 → 暂停 `paused_until`，发事件告警。
- **优先级**：登录/解锁类优先；批量/查询类低优；批量任务分片执行避免长期占用。

## 8. 事件总线

- 本地写事务内写 `events`（同事务，保证"状态变更必有事件"）。
- 发布器：轮询 `events where published_at is null` → 投递 webhook（签名/重试/死信）。
- 消费方幂等：`eventId` + `seq`；支持按 `sinceSeq` 拉取（轮询模式）。
- 事件保留：默认 30 天（可配置），之后归档/删除。

## 9. 索引与性能

- WAL；`busy_timeout=5000`；单写者（进程内串行写队列）。
- 关键索引：`customers(account_id)`、`customers(seas_flag)`、`customers(will_in_sea_at)`、`followups(customer_id, followed_at)`、`sync_outbox(status,next_retry_at)`、`events(seq)`、`tasks(status)`、`task_items(task_id,status)`。
- 分页列表默认走本地缓存（`stale_after` 可配置，如 60s）；`fresh=true` 强制上游。

## 10. 数据保留与清理

| 数据 | 保留 |
|---|---|
| 业务镜像（客户/联系人/跟进） | 长期（软删除标记） |
| 事件 | 30 天（可配） |
| 审计日志 | 180 天（可配） |
| 海关查询缓存 | 按 TTL（如 7 天） |
| 会话/健康记录 | 健康 30 天；sessions 保留当前 |
| 任务/task_items | 90 天（可配） |

## 11. 迁移与备份

- `schema_migrations` 顺序迁移脚本；启动时自动执行。
- 每日 `VACUUM INTO backup/fuma-YYYYMMDD.db`；保留 7 份；支持从备份恢复。
- token 加密 key 与 DB 分离存储，备份时同时备份 key（权限 600）。

## 12. 安全

- token/secret 加密（AES-GCM，key file 600）；日志/事件/API 脱敏（尾 4 位）。
- REST 仅 127.0.0.1；MCP 仅 stdio。
- 审计日志记录写操作（who/action/entity/account）。
- 敏感写操作（批量释放/删除）**不需要二次确认**（已确认，见 00 §5 D8）。

## 附：冲突与规则定稿 v4（2026-11-14 23:35）

### 冲突处理定稿（替代本文 §6.3 的“上游优先/本地优先”模糊表述）
1. **写路径本地优先**：事务内写本地事实 + outbox + 事件，立即返回（pending）。
2. **冲突收敛到上游**：对账发现上游事实（掉公海/被释放/他人跟进/归属变更）→ 以上游值更新本地；
   - 本地未同步指令 → `failed` + `sync.conflict` 事件 + 审计；
   - 不回滚已返回给编排层的本地事实（避免编排层状态错乱），只做状态收敛与告警。
3. 不设审批流状态（上游当前无审批）。
4. 删除为软删除（进回收站），不做二次确认。

### 规则新增
- **领取前强制查重**：RuleEngine.validateClaim 增加 dedup 校验（查重命中→拒绝，不写上游）。
- 容量：默认 500，实际按「角色→custLimit 规则」解析（已在 §附 v3）。
- 保护期：默认 15，实际按 seasRules.limitDays。
- 冷却：默认 3 天，按上游规则。

### 数据模型补充
- `reconcile_diffs.resolution` 取值：`upstream_wins`（默认）/`manual`；不采用 `local_kept`。
- `tasks`/`events` 保留不变；无审批表。

## 附：海关缓存数据模型 v5（2026-11-14 23:55）

> 替代 §2 中简化的 `customs_cache` 设计（保留旧表名可迁移），新增完整字段与失效元数据。

```sql
CREATE TABLE customs_cache_entries (
  cache_key        TEXT PRIMARY KEY,        -- sha256(queryType|params_hash|page|pageSize|permission_scope)
  query_type       TEXT NOT NULL,           -- company（MVP）| dict
  params_hash      TEXT NOT NULL,
  params_json      TEXT NOT NULL,           -- 规范化后参数（用于 purge/排查）
  page_index       INTEGER NOT NULL,
  page_size        INTEGER NOT NULL,
  permission_scope TEXT NOT NULL,           -- 如 cId:10264|role:xxx
  result_json      BLOB,                    -- gzip 压缩后的结果（或 JSON 文本）
  result_encoding  TEXT NOT NULL DEFAULT 'gzip',
  result_bytes     INTEGER,
  total_num        INTEGER,
  upstream_version TEXT,                    -- GetTradeUpdateLog 快照（AllCount/最新更新时间）
  fetched_at       TEXT NOT NULL,
  expires_at       TEXT NOT NULL,
  stale            INTEGER NOT NULL DEFAULT 0,
  hit_count        INTEGER NOT NULL DEFAULT 0,
  last_used_at     TEXT,
  last_error       TEXT
);
CREATE INDEX idx_customs_cache_expires ON customs_cache_entries(expires_at);
CREATE INDEX idx_customs_cache_used ON customs_cache_entries(last_used_at);
CREATE INDEX idx_customs_cache_type ON customs_cache_entries(query_type, params_hash);

-- 全局水位/元数据：更新日志水位、最近 purge、统计基线
CREATE TABLE customs_cache_meta (
  k          TEXT PRIMARY KEY,   -- update_log_all_count | update_log_latest | last_purge_at | ...
  v          TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

### 语义
- 写入：查询成功后同事务 upsert（按 cache_key）+ 更新 `last_used_at`；命中时 `hit_count+1`、`last_used_at=now`。
- 失效：
  1. `expires_at < now` → 过期；
  2. 上游 `GetTradeUpdateLog` 水位变化 → 标记 `stale=1`（惰性，下次查询刷新）；
  3. 手动 purge。
- 合并：同一 cache_key 在途请求合并（池内 future 共享）。
- 容量：默认 20 万条 / 2GB；后台按 `last_used_at` LRU 淘汰；保留 90 天。
- 权限域：`permission_scope` 必须参与 cache_key，防止跨权限读取。
- 统计：命中率、条目数、字节数、最近刷新、淘汰计数（写入 `customs_cache_meta` 或 metrics）。
- 与事件：缓存命中不发事件；刷新完成发 `customs.query.completed`（含 `cached/cacheRefreshed`）。

## 附：容量视图字段语义（v1.0.4 起，实测修正）

`account.list` / `account.get` 返回的 `capacity`：

| 字段 | 语义 |
|---|---|
| `limit` | 账号保护客户上限。`source=default` 表示使用默认 500（角色→custLimit 规则同步为 P7）；`source=config` 表示创建时显式指定 |
| `used` | 已占用容量：优先取**上游按 owner 统计的客户数**（`organizationStructure.ownerCtIdList`，`totalNum`），缓存 120s |
| `usedSource` | `upstream`=上游实时统计；`local_cache`=上游不可用/未登录时回退本地 `customers` 表估算（会被读缓存影响，仅供参考） |
| `remaining` | `max(0, limit - used)` |
| `lastSyncedAt` | 最近一次上游统计/规则同步时间 |

> 之前 `used` 直接统计本地 `customers` 表，读取客户列表也会落库，导致数字被缓存抬高（如 200 而非真实的 491）；v1.0.4 已改为上游优先。
