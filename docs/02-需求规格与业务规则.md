# 02 需求规格与业务规则

> 需求来源：[00-需求访谈记录.md](00-需求访谈记录.md)。版本：v5（正文 + v2/v4/v5 附录；10 项决策已确认）。本文为可验收的需求规格（FR/NFR/BR），P0 侦察结论作为约束输入。

## 1. 角色与系统上下文

| 角色 | 说明 |
|---|---|
| **fuma-platform** | 本系统。孚盟的薄封装 + 本地事实库 + 请求池 + 事件。 |
| **lead platform** | 调用方/编排方。决定业务动作，调用 fuma-platform 能力并消费事件。 |
| **孚盟（上游）** | 客保库 + 海关数据源。N 个真实业务员账号。 |
| **操作人/管理员** | 首次登录扫码、异常处理（掉线重登、风控告警）、账号扩容。 |

**核心事实**：
- 一个账号 = 一个真实业务员账号，平台建好后真人不再操作（平台独占）。
- 单账号保护容量默认 500 个客户；实际上限按上游「角色→custLimit 规则」解析（实测 300/200/500 三档）。
- 客户建档保护后默认 15 天无跟进自动掉公海（默认值；实际以 seasRules 的 limitDays 为准）。
- 自己的客户调入公海后默认 3 天内本人不可再领取（默认值；上游规则可配）。
- 账号数量 3–50；客保容量估算按默认 500 计（300/200/500 为实测角色规则档位）；上游风控/频率上限未知（保守）。

## 4. 业务规则（BR）

> 规则来源：①上游服务端规则（必须遵守，否则同步被拒）；②本地平台规则（为编排与一致性服务）。
> **重要**：规则数值（15 天 / 3 天 / 500）是孚盟后台可配置项，平台需读取/可配置，不硬编码。

| 编号 | 规则 | 类型 | 本地实现 | 备注 |
|---|---|---|---|---|
| BR-01 | 客户建档保护后 **15 天**无跟进 → 自动掉公海 | 上游服务端 | 本地计算 willInSeaAt + 定时扫描 + 到期事件；对账吸收上游实际掉保 | 数值可配置（seasRules/highseas） |
| BR-02 | 自己的客户调入公海后 **3 天内**本人不可领取 | 上游服务端 | 领取前校验释放时间 + 账号；冷却期内返回明确错误 | 数值可配置 |
| BR-03 | 单账号最多保护 **500** 个客户 | 上游服务端 | 容量账本 + 领取前校验 + 预警事件 | 数值可配置（custLimit） |
| BR-04 | 查重结果需定期复核 | 平台规则 | dedup_snapshot.checkedAt + 复核任务 + 变化事件 | 周期可配置 |
| BR-05 | 本地优先：变更先在本地成为事实；冲突最终收敛到上游 | 平台规则 | 本地事务 + outbox；对账收敛 + sync.conflict | 已确认（见 v4 附录） |
| BR-06 | 写操作必须指定账号；不替调用方选账号 | 平台规则 | API 强制参数 | 读任务可路由任意账号 |
| BR-07 | 公海客户不占保护容量；领取后才计入 | 上游规则 | 容量账本按保护客户计算 | 待上游确认边界 |
| BR-08 | 领取前强制查重（先查后领） | 平台规则 | claim 前置查重；命中→拒绝，不写上游 | 已确认（见 v4 附录） |
| BR-09 | 每账号独立登录态/限速/缓存；禁止跨账号串数据 | 平台规则 | 账号隔离 | — |
| BR-10 | 事件必须可重放、消费幂等 | 平台规则 | outbox + eventId + sequence | — |

## 5. 验收标准（示例）

- AC-01：管理员新增账号并触发登录 → 平台返回二维码（payload 可复制、base64 可渲染）→ 扫码确认 → 账号状态变为 online，token 落库（加密），保活任务启动。
- AC-02：调用 `customer.list(accountId=A, filters)` → 返回分页列表；`meta.totalNum` 与上游一致；第二次调用命中本地缓存（可配置）。
- AC-03：调用 `open_sea.claim(accountId=A, customerId=C)` 且 A 容量已满 → 返回 `capacity_exceeded`，不产生上游写请求。
- AC-04：调用 `followup.create(accountId=A, customerId=C, content, nextFollowupAt)` → 本地立即产生跟进记录与事件；异步同步成功后将对应客户 `willInSeaAt` 后移；对账不一致时发出 `sync.conflict` 事件。
- AC-05：批量查重 200 条 → 返回 taskId；轮询 task 至 completed → 结果完整、错误条目独立可查。
- AC-06：kill -9 进程重启 → 任务/outbox/本地事实仍在；未完成任务状态可查（可恢复执行）。
- AC-07：token 过期 → 会话状态变 expired + 事件；重新登录后恢复。

## 附：v2 增补（来自现场抓包与登录专项）

### NFR-11 登录性能（硬指标）
- 预启动后二维码就绪 ≤5s；扫码确认→online ≤8s；免扫码重登（若可行）≤15s/账号。
- 多账号重登并发 ≤2；到期时间错峰（提前 45min 触发）。

### NFR-12 保活可用性
- 在线率目标 ≥98%（50 账号场景）；心跳每 3–5min；连续 3 次失败降级并告警。
- token 到期前 1h 发事件；过期自动入重登队列。

### FR 补充

- FR-S-12：免扫码重登实验开关（silentRelogin），失败自动降级二维码。
- FR-S-13：多账号到期错峰调度。
- FR-D-06：查重结果变化事件（count 变化时发布）。
- FR-H-05：海关查询结果本地缓存 + TTL；大结果任务化。
- FR-C-08：客户详情按需拉取 + 本地缓存（stale 可配置）。

### 验收补充
- AC-08：50 账号批量导入后，登录队列并发≤2 平滑完成，无风控触发。
- AC-09：token 到期前自动重登成功（或按设计降级为人工扫码），期间读请求返回明确 `session_expired`。
- AC-10：kill -9 后重启，未过期账号直接 online（无需扫码）。

### 业务规则来源修正（v3 实测）

- **保护期天数**：不是写死 15，而是上游公海规则 `seasRules/getAll → seaRuleConditionGroupList[].limitDays`（本企业=15）。平台按「账号角色 → 适用规则 → limitDays」解析，读不到才用默认 15 并标注 `configSource=default`。
- **容量上限**：不是统一 500，而是上游 `custLimit/list` 按角色配置的多条规则（实测本企业存在 300/200/500 三档 `totalLimit`）。平台按「账号角色 → 命中规则 → totalLimit」计算账号上限，读不到才用默认 500。
- **公海范围**：`custScope/applyRoles` 同样来自公海规则，需解析后用于本地规则引擎。
- **筛选能力**：上游提供 51 个客户字段 × 48 个 comparator（含相对日期），平台对外暴露 `filters` + `systemSelection` 两套筛选入口。

## 附：决策落库 v4（2026-11-14 23:35，替代此前待确认项）

> 以下为已确认需求；与正文旧表述冲突时以本节为准。

### 1) 同步与冲突（替代 BR-05 / FR-Y-04）
- **本地优先**：写操作先落本地事实并立即返回，不阻塞调用方。
- **冲突最终收敛到上游**：对账发现上游事实与本地不一致（如上游已掉公海/已被释放/他人已跟进）→ **以上游为准**更新本地；本地未同步的写指令转 failed/告警，**不回滚已返回的事实**，记录 `sync.conflict` 与审计。
- 上游没有“审批流”（当前），因此写操作不存在待审批状态。

### 2) 查重（替代 BR-08 / FR-O-02）
- **领取前强制查重（先查后领）**：claim 前置校验中查重命中 → 拒绝（`duplicate_customer`），不产生上游写请求；查重快照落库。

### 3) 范围裁剪（替代 FR-H-03 / FR-H-01 的“按产品查/分析”）
- **海关数据 MVP 仅“按公司查询”**（tradeList 公司维度）；产品/HS/交易分析 **不做**（P3 之后再评估）。
- **贸易监测不进 MVP**（P3 只读接入候选）。
- 保留海关字典类只读接口（国家、HS、数据源、更新日志）用于展示与校验。

### 4) 账号信息与安全（替代 D7/D8）
- 账号/归属信息**暴露业务员真实信息、不脱敏**（ownerName 等直接返回）。
- **敏感写操作不需要二次确认/双人确认**；平台仅做接口级校验与审计。

### 5) 事件与保活（替代 D5/D6）
- 事件：**轮询 `GET /v1/events` 为首选**；webhook 预留在配置中，MVP 可不启用。
- 浏览器：**不要求常驻**用于保活；保活以 HTTP 心跳为主（结论见 06 v4）。常驻仅作为“免扫码重登/快速出码”的可选优化（开关默认关）。

### 6) 验收补充
- AC-11：claim 未查重/查重命中 → 拒绝且无上游请求。
- AC-12：对账发现上游事实变化 → 本地收敛到上游，产生 `sync.conflict` 且本地写指令状态可查。
- AC-13：账号列表返回 ownerName 等业务员真实信息。

## 附：需求补充 v5 —— 海关数据本地缓存（2026-11-14 23:55，用户新增）

> 与正文 FR-H-04/05 合并生效；冲突时以本节为准（缓存从“可选项”升级为**强制能力**）。

### FR-H-06 海关查询结果强制本地缓存
- 范围：MVP 仅「按公司查询」链路（ImpEnterprise/ExpEnterprise/tradeList/公司详情/字典）。
- 查询成功后，将结果按 **查询键 = queryType + 规范化参数 + 分页 + 权限域** 写入本地 SQLite 缓存；
  同一查询再次请求时**不调用上游**，直接返回缓存。
- 响应必须标记数据来源：`source: upstream|cache`、`cached: bool`、`cachedAt`、`expiresAt`。
- TTL 默认（可配置）：查询结果 **24h**；字典类 **7d**；计数/统计 24h。
- 支持 `forceRefresh=true` 跳过缓存强制上游并刷新缓存。

### FR-H-07 缓存失效与一致性
- **上游更新日志失效**：定期读取 `tradeData/api/V2/Account/GetTradeUpdateLog`（AllCount / 最新 updatetime），
  与缓存中的 `upstream_version` 比较，变化则将相关公司查询缓存标记 stale（惰性刷新）。
- TTL 到期即失效；失效后下次查询重新拉取。
- 上游失败（超时 / code -1 / 1004 / 网络错误）时：
  - 有未过期缓存 → 返回缓存（`stale=false`）；
  - 仅有过期缓存且 `allowStale=true`（默认 true）→ 返回缓存并标 `stale=true` + 告警事件；
  - 无缓存 → 返回上游错误。
- **并发合并**：相同查询键的并发请求合并为一次上游调用（in-flight dedupe）。

### FR-H-08 权限隔离与安全
- 缓存键必须包含权限域（`cId + 账号角色/数据权限标识`），禁止跨权限域复用缓存。
- 指定 `accountId` 的查询：先校验该账号海关数据权限；无权限即使缓存命中 → `permission_denied`。
- 不指定账号的纯缓存读取：默认**不允许**（`allowAnonymousCache=false`）；可由编排层显式启用。
- 缓存内容不写入 token/cookie；数据仅本机、随 DB 备份策略管理。

### FR-H-09 容量与运维
- 默认上限：**20 万条缓存条目 / 2GB**；超限按 LRU（last_used_at）淘汰。
- 缓存统计：命中率、条目数、占用、最近刷新时间（`GET /v1/customs/cache/stats`）。
- 手动清理：`POST /v1/customs/cache/purge`（可按 queryType / 公司 / 时间范围）。
- 缓存条目保留：默认 90 天后清理（可配置）。

### 验收标准
- AC-19：同一公司查询第二次 → 无上游请求，响应 `cached=true`、`source=cache`，内容与首次一致。
- AC-20：`forceRefresh=true` → 强制上游并刷新缓存。
- AC-21：TTL 过期或上游更新日志变化后查询 → 自动刷新；刷新失败时按 FR-H-07 降级返回 stale 缓存。
- AC-22：模拟上游超时 → 有缓存时返回缓存（stale 标记正确），无缓存时返回明确错误。
- AC-23：无海关权限账号即使在缓存命中情况下仍返回 `permission_denied`。
- AC-24：缓存达到上限后按 LRU 淘汰，查询结果正确性不受影响；purge 后不再命中。
